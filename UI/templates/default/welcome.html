What is a Model Card?

A model card is a short and compact document that provides essential information about a machine learning model. It is intended to improve transparency, communication, and responsible AI usage by documenting key details about the model’s purpose, intended use, possible misuses, performance, limitations, ethical considerations and more.

Why are Model Cards important?

Model cards help users and stakeholders to understand the capabilities and boundaries of an AI system. They promote responsible AI by encouraging creators to reflect on their models’ real-world impact.

Prototyping transparency services for AI-model cards

This is the prototype implementation of the Transparency Services for AI-model Cards for creating, editing, and managing model cards. The service’s goal is two-fold. First, to assist AI model creators such as engineers, researchers, and developers to produce transparent AI models by equipping them with tools to create model cards, and second to provide model cards that are comprehensible for both AI-experts and non-experts like journalists, data scientists, and media professionals.

What does a Model Card include?

Model Card Fields Content
Model Details
  • Model Name
  • Overview
  • Person or organization developing model
  • Date of model development
  • Model version
  • Model type
  • Paper or other resources for more information
  • Citation details
  • License and IP
  • Feedback on the model (e.g. email contact)
Considerations Intended Use
  • Primary intended uses and purpose
  • Oversight level (e.g. self-learning, human-in-the-loop)
  • Primary intended users
  • Out-of-scope use cases
Usage Information
  • Software requirements
  • Hardware requirements (Training and Inference)
  • Technical usage instructions (e.g. code snippet)
  • Inputs and outputs
  • Factors that influence performance
Ethical Considerations
  • Ethical Risks
  • Ethical Assessments
  • Definition of fairness
Training Set
  • Datasets
  • Motivation (why those datasets)
  • Data pre-processing (e.g. tokenization, cropping)
  • Reliance on standards (e.g. ISO, IEEE)
  • Data update (quality and relevance)
Eval Set
  • Datasets
  • Motivation (why those datasets)
  • Data pre-processing (e.g. tokenization, cropping)
  • Reliance on standards (e.g. ISO, IEEE)
  • Data update (quality and relevance)
Quantitative Analysis Metrics
  • Model performance (e.g. Accuracy, F1 score)
  • Decision thresholds
  • Uncertainty and variability (e.g. std dev, variance)
Analysis
  • Disaggregated results and fairness
